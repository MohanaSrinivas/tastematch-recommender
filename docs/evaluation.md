# Evaluation protocol
The split is chronological within each user. The final 20% of each user's events (rounded, at least one) form the test set while at least one event remains in train. Test ratings >= 4.0 are relevant. Precision@K divides hits by K, Recall@K divides hits by relevant test items, and NDCG@K discounts hits by log2(rank+1). Metrics are macro-averaged over users with at least one relevant held-out item. This is a leave-latest-out offline protocol, not a randomized IID estimate.

For content-based evaluation, the query is the user's most recent training movie rated >= 4.0. Recommendations are compared with the user's relevant held-out movies. Users without a liked training movie are excluded from this content metric because the item-to-item model has no valid positive query for them. Collaborative evaluation uses the user's training ratings to produce recommendations directly. These methods therefore have different eligible-user populations; compare their scores with that limitation in mind.

The earlier content calculation used the first held-out movie as its query. That item is unavailable at recommendation time, so the resulting content-based Precision@K was not a valid leave-latest-out estimate.
